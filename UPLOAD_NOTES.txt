WHAT CHANGED
- Apply Vault now visually matches the main portfolio: light background, IBM Plex Mono, orange accent, restrained grid system.
- Login is presented as a secure command terminal.
- After credentials are submitted, an animated authorization console opens and displays a fast verification trace.
- Approved users get a dedicated access-granted transition before entering the private page.
- Denied users get an animated authorization request form.
- Request fields: first name, last name, mobile number, email, university/affiliation, university entry year, reason for access.
- Requests submit automatically; users no longer need to open Gmail or a mail app.
- Each request is stored in the connected Google Sheet and sent to the owner as a formatted HTML email.
- Requests include a unique reference ID.
- Existing Vault Access logic is preserved: Email | Password | Status | Note.
- Email remains the username, so approving a visitor only requires adding their email, assigning a password, and setting Status to ALLOW.
- The old six-column Access Requests layout is migrated when setupVault() runs.

IMPORTANT AFTER UPLOAD
The frontend can be committed directly to GitHub, but the Google Apps Script backend must also be updated:
1. Open the connected Sheet -> Extensions -> Apps Script.
2. Replace the script with google-apps-script.gs.
3. Run setupVault() once.
4. Deploy -> Manage deployments -> edit existing Web App -> New version -> Deploy.

Keep the existing /exec URL in access-config.js.
